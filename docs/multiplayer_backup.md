# 수비 백업 모드 — 하이브리드 협동 멀티플레이 설계

**목표(B안)**: 1명 VR + 나머지 PC 가 **같은 타구 상황을 동시에** 수행한다. 각자 다른 수비
포지션을 맡고, 각자 자기 백업 위치로 이동하며, 판정·점수는 개인별로 남는다.

**왜 이 종목인가**: 백업은 원래 혼자 하는 판단이 아니다. 그리고 규칙 테이블이 이미
`Resolve(Rules, Play, Position)` 로 **하나의 타구에서 7개 포지션 각각의 정답**을 계산한다 —
멀티플레이에서 제일 비싼 "여러 명분의 정답 데이터"가 이미 있다.

---

## 불변 조건 (사용자 확정 — 어떤 단계에서도 깨면 안 됨)

> **협동은 여러 대가 실제로 인식됐을 때만 활성화된다. 혼자 붙었을 때는 기존 기능이
> 혼자서 그대로 잘 돌아가야 한다.**

이건 "되면 좋은 것"이 아니라 회귀 금지선이다. 지키기 위해 코드에 넣은 장치:

| 장치 | 위치 | 막는 사고 |
|---|---|---|
| `bLocalSessionFallback` | `BackupPawn` | GameState 를 못 찾으면(다른 맵/GameMode, 스폰 실패) 폰이 예전 방식으로 직접 진행. **협동 배선이 없어도 드릴은 돈다** |
| `PruneRegisteredPawns()` | `BackupGameState` | 인원수를 세기 **전에** 유령(파괴된 폰의 약참조)을 걷어낸다. 안 하면 혼자인데 협동으로 오인해 오지 않을 보고를 영원히 기다린다 = 혼자 플레이가 멈춘다 |
| 등록 폰 1개 → 기존 편향 추첨 위임 | `DrawNextPlayIndex()` | 혼자일 때 `HoldTrialFraction` 규칙이 그대로 유지된다. 협동 규칙(전체 테이블 추첨)이 혼자에게 새지 않는다 |
| 등록 폰 1개 → 즉시 다음 시행 | `ReportTrialFinished()` | "전원 보고 대기"가 혼자일 때 대기 0 이 된다 |
| `TrialHardTimeoutSec` (20s) | `BackupGameState` | 협동에서 누가 멈춰도 세션이 영영 안 멈춘다. 단독 시행의 최대 제한 시간(약 9.4s)보다 충분히 크다 |

**검증 방법**: PIE 1인으로 백업 드릴을 끝까지 한 판 — 시행 수·간격·Hold 비율·결과 저장·AI
코칭이 이 변경 **이전과 동일**해야 한다. 하나라도 다르면 회귀다.

## 현재 구조와의 충돌 지점 (실측)

| # | 사실 | 영향 |
|---|---|---|
| 1 | 전체 소스에 `bReplicates`/`HasAuthority`/RPC **0건** | 순수 싱글플레이. 복제 골격을 새로 세워야 함 |
| 2 | **`GetAuthGameMode()` 호출 13곳** (`ModeSelectPawn` 6, 각 드릴 폰의 복귀 경로 등) | **클라이언트에서 항상 null** → 모드 진입·복귀가 전부 죽는다. 최대 난관이며 백업 모드 전용 문제가 아니다 |
| 3 | `UModeManager` 가 GameInstanceSubsystem (클라이언트별) | 포지션 배정을 여기 두면 두 명이 같은 포지션을 고를 수 있다 |
| 4 | 플레이 추첨이 폰 로컬 `FMath::RandRange` (`BackupPawn.cpp:422`) | 각자 다른 상황을 보게 된다 |
| 5 | 커스텀 `APlayerController` 없음 | `Server_` RPC 를 놓을 자리가 없다 |
| 6 | 이동이 `AddActorWorldOffset` 직접 호출 (CharacterMovement 아님) | 표준 이동 복제가 안 붙는다 |
| 7 | `AFielderMarker` 가 나머지 6포지션에 동료를 이미 세움 | **유리한 점** — 실제 플레이어로 갈아끼울 자리가 이미 있다 |

## 권한 분리

| 계층 | 권한 | 근거 |
|---|---|---|
| 플레이 선택·시행 타이밍 | **서버 (GameState)** | 전원이 같은 상황을 같은 순간에 봐야 한다 |
| 포지션 배정(중복 방지) | **서버 (GameMode)** | 두 명이 동시에 유격수를 맡을 수 없다 |
| 판정(방향·도착·경로효율) | **각 클라이언트 로컬** | 입력이 로컬 HMD/컨트롤러다. 로컬 계산이 정확하고 지연도 없다 |
| 점수·저장·AI 코칭 | **각 클라이언트 로컬** | 지금 구조 그대로. 개인 기록은 개인 것 |
| 동료 위치 표시 | 서버 경유 복제 | 마커 → 실제 플레이어 폰 |

**치팅 방어는 하지 않는다.** 전시 부스 협동 콘텐츠라 클라이언트 권한 이동으로 충분하고,
서버 권한 이동은 VR 에서 지연으로 멀미를 만든다.

## 핵심 설계 결정

### 1. 플레이는 **인덱스만** 복제한다

`FBackupPlay` 구조체를 복제하지 않는다. `UBackupPlaybook::BuildPlayTable()` 은 코드에 박힌
결정론적 데이터라 모든 클라이언트가 **동일한 테이블**을 갖는다. 서버는 `int32 PlayIndex` 만
보내고 각 클라이언트가 자기 포지션으로 `BuildTrial()` 한다.

→ 대역폭 최소, 정답 계산은 로컬, 규칙 저작 변경 0.

### 2. 싱글플레이와 멀티플레이의 **추첨 규칙이 다르다**

지금은 `HoldTrialFraction=0.2` 로 "내가 할 일이 있는 플레이" 80% + Hold 20% 를 섞는다.
혼자 할 땐 필수다 — 안 그러면 1루수가 대부분의 시행에서 아무 일도 안 하게 된다.

**멀티플레이에선 이 보정을 끈다.** 하나의 타구에 7명 전원이 동시에 걸려 있으므로, 전체
테이블에서 그냥 뽑으면 각자에게 할 일이 있기도 없기도 하다 — 그게 실제 야구다.
`HoldTrialFraction` 이 하던 훈련 타당성(가만히 있는 것도 정답일 수 있다)이 공짜로 나온다.

### 3. GameState 로 옮기되 **`HasAuthority()` 로 감싼다**

스탠드얼론에서도 `GameStateBase` 는 항상 존재하고 `HasAuthority()` 는 true 다.
→ **같은 코드가 싱글플레이에서 지금과 완전히 동일하게 동작한다.** 분기 없는 이행.

### 4. 접속은 커맨드라인으로 (UI 없음)

- 호스트: `MotionBase.exe <맵>?listen`
- 클라이언트: `MotionBase.exe <호스트IP>` — UE 가 기본 지원한다

부스는 고정 장비라 이게 가장 안정적이다. 접속 UI 는 나중에 얹으면 된다.

## 단계

각 단계가 **끝날 때마다 플레이 가능한 상태**로 끝난다.

| 단계 | 내용 | 검증 |
|---|---|---|
| **1. 시행 진행권 이관** | `ABackupGameState` 신설. 플레이 추첨·시행 번호·시행 타이밍을 폰에서 GameState 로. 복제 마크업 포함하되 아직 싱글로만 동작 | PC 단독 — 지금과 **동일하게** 동작해야 함 |
| **2. 복제 골격** | `AMotionBasePlayerController`(Server_ RPC 자리), `ABackupPlayerState`(포지션·점수), GameMode 포지션 배정, 폰 트랜스폼 복제 | **PIE > Number of Players 2~3** — 헤드셋 없이 데스크톱에서 전체 검증 가능 |
| **3. 진입 경로 수술** | `GetAuthGameMode()` 13곳을 PlayerController RPC 경유로. 클라이언트도 메뉴→드릴 진입 가능하게 | PIE 다중 클라이언트로 메뉴부터 진입까지 |
| **4. 동료 표시** | `AFielderMarker` 를 실제 플레이어로 대체(빈 포지션만 마커 유지), 이름표에 플레이어명 | PIE |
| **5. 팀 결과 화면** | 시행마다 전원 결과 요약(누가 어디로 갔는지), 세션 종료 시 팀 보드 | PIE |
| **6. VR 호스트 + PC 클라 통합** | 실기 검증, 지연 보정(`VRInputLatencyBiasSec` 재측정) | 하드웨어 필요 |

**2단계가 핵심 이정표**다 — 여기까지 오면 VR 없이 데스크톱 한 대에서 멀티플레이 로직 전체를
PIE 로 검증할 수 있다.

## 미해결 / 하드웨어 필요

- 네트워크 지연이 판단 시간 측정에 주는 영향 (큐 시점을 서버 시간으로 통일하므로 이론상 0이지만 실측 필요)
- VR 호스트가 동시에 서버를 돌릴 때의 프레임 여유
- 클라이언트 수 상한 (설계상 7, 실제 부스 장비 수에 따름)
