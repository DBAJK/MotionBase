## 2. 플랫폼 특성 (설계 시 반드시 준수)

`SporTrack`은 일반 VR 게임이 아니다. 아래 특성에 맞춰 설계해야 한다.

- **비착용형(Non-HMD)**: 헤드셋을 쓰지 않고 바닥형/공간형 투사로 몰입 환경 구현
- **전신 동작 인터랙션**: LiDAR 기반으로 사용자의 위치·움직임을 추적
- **보드게임 포맷**: 스포츠 테마 구역으로 구성된 맵에서 이동하며 칸별 퀘스트 수행
- **다인원 멀티플레이**: 1명 ~ 최대 10명 동시 플레이
- **교육 융합**: 2023 개정 교육과정 체육 요소 반영 (학교/공공기관 활용)

> ⚠️ **핵심 긴장점**: 본 프로젝트는 HTC Vive 컨트롤러를 배트 입력으로 사용한다.
> 이는 "비착용형" 정체성과 부분 충돌하므로, 심사/제출 시 설명 논리를 준비할 것.
> (대안: Vive Tracker를 신체/도구에 부착 → 헤드셋 미착용 상태로 base station 트래킹만 활용하는 하이브리드 구성)

## 3. 기술 스택

| 구분 | 내용 |
|------|------|
| Engine | Unreal Engine 5.x (C++ + Blueprint) |
| VR/Tracking | HTC Vive (Vive Pro) — SteamVR / OpenXR |
| Tracking 방식 | Base station(Lighthouse) 룸스케일 + Vive 컨트롤러 입력 |
| 배트 입력 | Vive 컨트롤러 (스윙 궤적·속도·타이밍 추적) |
| 신체 추적 | LiDAR (뉴작 제공 환경) — 전신 위치/동작 |
| 생성형 AI | 플레이 데이터 기반 맞춤 피드백 텍스트 생성 (API 연동) |
| 개발 장비 | 고사양 GPU 탑재 개발용 노트북 |

**연동 스택 요약**: `개발 노트북 → Unreal Engine 구동 → SteamVR(Vive) + LiDAR 입력 연동 → 바닥 투사 렌더링`

## 4. 핵심 기능 (게임 모드)

야구 흐름(수비 → 주루 → 타격)을 6개 모드로 구현. 난이도·운동 강도가 단계적으로 누적.

### 1. 신체 인식 (셋업)
- **구현**: LiDAR로 사용자 위치·키·동작 범위 스캔 → 플레이 영역 자동 보정
- **활용**: 개인별 난이도 기준선(이동 반경·반응 기준) 설정
- **입력**: LiDAR

### 2. 반응속도 훈련
- **구현**: 바닥에 무작위 점등되는 목표 지점을 제한시간 내 밟기, 콤보 가중
- **측정**: 반응시간(ms), 정확도, 최대 연속 성공
- **난이도**: 점등 간격 단축 → 다중 타깃 → 페이크 타깃
- **입력**: LiDAR (발 위치)

### 3. 수비 훈련
- **구현**: 좌/우/중앙 가상 타구를 좌우 이동·점프·숙이기로 처리
- **측정**: 포구 성공률, 동작 정확도, 자세 안정성
- **입력**: LiDAR (전신 자세)

### 4. 베이스 러닝
- **구현**: 투수 모션 신호에 맞춰 진루·귀루, 타이밍 판정으로 세이프/아웃
- **측정**: 스타트 반응, 주루 속도, 판단 정확도
- **입력**: LiDAR (위치·이동)

### 5. 타격 훈련 ★ Vive 핵심
- **구현**: Vive 컨트롤러 = 배트. 구종(직구/변화구)별 스윙 → 가상 타구 결과
- **측정**: 컨택 정확도, 스윙 타이밍, 가상 타구 비거리
- **난이도**: 구속 증가 → 변화구 비율 상승 → 코스 다양화
- **입력**: Vive 컨트롤러 (스윙 궤적/속도/타이밍)

### 6. 기능성 피트니스
- **구현**: 스쿼트·런지·사이드스텝·점프를 야구 동작과 결합한 인터벌 운동
- **측정**: 반복 횟수, 자세 정확도, 추정 운동량
- **입력**: LiDAR (관절 각도·반복 카운트)

## 5. 기술 아키텍처 (구현 레이어)

```
[Input Layer]
  - SteamVR Input (Vive 컨트롤러 / Tracker)
  - LiDAR Data Ingestion (위치·골격·동작)
      ↓
[Game Logic Layer]
  - Mode Manager (6개 모드 전환/상태 관리)
  - Difficulty System (스캔 기준선 + 누적 기록 기반 동적 조정)
  - Scoring / Judgement (모드별 채점 로직)
      ↓
[Data Layer]
  - Play Result Logger (반응시간·정확도·반복수 등 사용자별 누적 저장)
      ↓
[AI Feedback Module]
  - 누적 데이터 → 프롬프트 구성 → 생성형 AI API 호출 → 피드백 텍스트 표시
      ↓
[Render / Output]
  - 바닥/공간 투사 렌더링
  - Multiplayer 세션 (1~10명)
```

## 6. 개발 우선순위 (1인 / 12주 기준)

- **1차 (MVP)**: 프로젝트 셋업 + Vive 연동 검증 + `타격 훈련` + `반응속도 훈련`
  → 핵심 재미와 Vive 입력 파이프라인을 먼저 검증
- **2차**: `수비 훈련` + `베이스 러닝` (LiDAR 전신 추적 로직)
- **3차**: `기능성 피트니스` + `생성형 AI 피드백` 고도화
- **확장**: 멀티플레이 대전/랭킹, 교육용 커리큘럼 모드

## 7. Claude Code 초기 작업 (제안 순서)

1. **UE5 C++ 프로젝트 스캐폴딩** — 기본 프로젝트 구조, 모듈 분리
2. **SteamVR/OpenXR 플러그인 설정** + Vive 컨트롤러 입력 매핑(Input Action)
3. **Mode Manager 구조 설계** — 6개 모드 전환/상태 머신
4. **타격 모드 프로토타입** — Vive 컨트롤러 스윙 궤적·속도·타이밍 감지 로직
5. **Play Result Logger** — 결과 데이터 스키마 정의 + 로컬 저장(JSON 등)
6. **AI 피드백 모듈** — 누적 데이터 → API 호출 → 결과 파싱/표시 (async)
